Architecture overview

Recall ranks memories by section, then follows their links

A query searches only active memories. It combines keyword and meaning-based search, so an exact name and a loose description can both find the same note.

The steps

  1. Each memory is matched section by section, using keyword, vector, title and phrase signals fused by Reciprocal Rank Fusion (packages/core/src/store/corpus-index.ts:7, packages/core/src/store/index/hybrid-index.ts).
  2. Wikilink neighbours of direct matches are added in both directions, with a decayed score (packages/core/src/store/index/recall.ts).
  3. Results are over-fetched by four times the limit, with a floor of 24, so that filtering can still fill the limit. The default limit is 8 (corpus-index.ts:356-357).
  4. A memory with an open flag moves down the ranking but is never removed.
  5. With several shelves, each shelf's results are merged into one labelled list.
Why Reciprocal Rank Fusion?
Decision
Combine the signals by rank position.

Why embed locally?

Why are references searched separately?

Recall covers memories only. search_references builds its own references-only index for each call.
Constraint
Long documents would otherwise compete with short memories. The code states the separation; this reason is inferred.

Known limits

The candidate pool is bounded, so a very selective tag filter can return fewer results than the limit even when more matches exist (noted in corpus-index.ts:347-350). The in-memory index is built from the vault, so a large vault costs start-up work and memory.
