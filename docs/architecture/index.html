The Librarian gives AI coding agents one memory they all share

It's a small self-hosted server. Agents in any supported harness read and write it over MCP, conversations are captured automatically, and a model-driven curator files what's worth keeping into a folder of markdown files under git.

Five parts make up the system

  • The server answers agents on one port and the dashboard on another, and runs every background job.
  • The vault and store: markdown under git is the truth. Everything else can be rebuilt or thrown away.
  • The curator decides what gets filed, where, and whether a person needs to review it.
  • Harness integrations are thin adapters that ship conversation text and teach agents the protocol.
  • The dashboard is the only admin surface.

Two flows carry most of the value

  • A conversation becomes memories, from the harness hook to a committed file.
  • An agent recalls a memory, from the query to ranked results.

The shape comes from one deliberate simplification

Six months of feature drift ended in a deletion-heavy rethink. What survived is a markdown and git vault, a small fixed set of agent verbs, one curator with one apply rule, and one short primer.

Why so few moving parts?
Decision
Carve the codebase down to a markdown and git vault of memories, handoffs and references, served over MCP, kept healthy by one curator with one apply rule.
Constraint
Audits found dead features, half-finished migrations and split-brain risk from a surviving SQLite path.
Rejected
A full rewrite: the audits found the foundation was strong, so the work was carving down, not starting again.
Cost accepted
About a third of the server code and most of the plugin code was deleted, along with the features they carried.
Source
ADR 0007 (observed). The verb count has since grown to 8 (ADR 0016).
