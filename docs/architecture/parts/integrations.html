Architecture overview

Harness integrations are thin adapters over one server contract

Each harness needs an MCP connection for the verbs and a way to send conversation text. Everything after that happens on the server, so only the small piece that collects a turn differs.

Each harness collects turns its own way

Harness Trigger Source of text
Claude Code UserPromptSubmit; Stop and SessionEnd as backup Transcript file, from a byte-offset cursor
Codex UserPromptSubmit, reusing the Claude adapter Per-turn delta
OpenCode chat.message plugin hook Session message list
Pi agent_end event Messages in the event
Hermes sync_turn Arguments to the call

Why capture with hooks rather than asking the agent?
Decision
Capture happens at the harness boundary, with the server doing the extraction.
Constraint
Agents forget to save, and the server can only see MCP calls.
Rejected
Advice alone (already failed); a broad file-write veto; server-side enforcement (impossible); agent-driven capture as the main path.
Cost accepted
A server-side model cost that scales with conversation volume.
Source
ADR 0009 (observed; the ADR's status still reads Proposed although capture has shipped)
Why does Claude capture on UserPromptSubmit?
Decision
Use the prompt event as the main trigger, so capture runs one turn behind.
Constraint
Plugin-scoped Stop hooks register but never fire (Claude Code issue #29767).
Rejected
A Stop-only adapter, which would silently never run.
Cost accepted
The most recent turn waits for the next prompt or session end.
Source
docs/harness-capture-capability.md (observed)

Session start teaches the agent; a guard stops a competing memory

In Claude Code, SessionStart prints an awareness banner and injects the recent journal, and it fires again after a compaction. A PreToolUse guard blocks writes to Claude's native memory store and tells the agent to use remember. The guard allows the write on any error of its own.

Source: integrations/claude/scripts/on-session-start.mjs, on-session-start-journal.mjs, block-memory-write.mjs.

Private mode is enforced twice

Adapters drop private turns before sending, and the server also drops any turn carrying the [librarian:private=on] marker.

Source: packages/mcp-server/src/http/transcript-intake.ts:62-67,125.

Known limits

Live capture has been confirmed end to end only for Claude Code; live checks for the other harnesses are still on the maintainer's TODO. Transcripts exclude tool output, thinking and subagents for the Claude adapter.
