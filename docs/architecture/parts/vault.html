Architecture overview

The markdown vault is the truth, and everything else can be rebuilt or thrown away

Every memory, handoff, reference and journal entry is a readable markdown file in a git repository. Each write is its own commit, which is what makes history, restore and backup simple.

The vault has a fixed top-level shape

Path Holds
memories/ One file per memory; status active, proposed or archived in frontmatter
handoffs/ Five-heading handoff documents, each claimable once
references/ Long documents, searched separately from memories
journal/ Day, week and month summaries of conversations
inbox/ Submissions waiting for the curator
primer.md The protocol taught to every agent

Source: packages/core/src/store/vault-files.ts:197-218. Outside the vault, the data directory holds settings.json, intake-runs.json, the NDJSON logs and transcripts/.

Why markdown and git instead of a database?
Decision
Markdown is the source of truth and the SQLite backend was removed.
Constraint
A dual-path store had already produced split-brain on a real install, and markdown keeps the data readable and editable in tools such as Obsidian.
Rejected
Keeping SQLite alongside markdown.
Cost accepted
An in-memory index has to be built from files, and each write pays for a synchronous git commit.
Source
ADR 0007 (observed)
Why isn't the vault encrypted?
Decision
Provider tokens and agent tokens are encrypted with a master key; memories are plaintext.
Constraint
The realistic threat is theft of the whole volume, and encrypted files would break editing in Obsidian.
Rejected
Encrypting the vault at rest: it breaks the plaintext design and doesn't help if the key sits beside the data.
Cost accepted
Anyone who can read the volume or the backup remote can read the memories.
Source
ADR 0008 (observed)

A write is synchronous and backup is a push

The store is synchronous and commits by shelling out to git. Backup pushes HEAD to a configured remote, and restore is a clone.

Source: packages/core/src/store/git/sync-git-ops.ts, packages/core/src/backup/run.ts.

Shelves are prefixes inside the one repository

A shelf is a path prefix inside the vault. The open-source default has one shelf, the vault root. A plugin's router can give a user several, such as a personal shelf and a read-only team shelf.

Source: packages/core/src/vault-router.ts; decision in ADR 0011.

A handoff can only be claimed once

A handoff must contain five headings: Start & intent, Journey, Current state, What's left, and Open questions. The schema refuses anything else. A second claim is refused, and the error says who already holds it.

Source: packages/core/src/schemas/handoff.ts:17, packages/core/src/store/markdown/markdown-handoff-store.ts:107.

Known limits

Sidecar logs and settings are not in the vault, so they are not in the git backup. By design, a restored server regenerates its credentials and you re-enter third-party ones (ADR 0008).
